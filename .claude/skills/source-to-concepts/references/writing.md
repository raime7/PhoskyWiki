# 解读写作规范

写 `claim-map.json` 时读。会话只写一句话核心、论点标题、解读和摘录位置；引用块、出处行、资料覆盖范围、译本和生成方式说明都由程序生成。成稿结构见 `scripts/book-pipeline/template.ts` 文件头注释，范例见 `scripts/book-pipeline/fixtures/assemble/claim-map.kaiduan.json`。

## 硬上限

由 `validate` 检查（`scripts/book-pipeline/validate.ts` 的 `LIMITS`，按不含空白的可见字符计）：

| 项 | 上限 |
| --- | --- |
| 论点 | 5 个 |
| 每个论点的摘录 | 3 段 |
| 单段摘录的可见引文 | 200 字（不含“……”） |
| 一句话核心 + 全部解读 | 1500 字 |

上限是为了让核心清楚、不臃肿。写不下时先删次要论点、换更短的句子范围，而不是申请放行。

## 一句话核心

一个段落、一句话：诠释者如何理解这个概念。它同时是词条页上该视角的摘要，所以要让没读正文的人也能抓住要点，例如“黑格尔把定在（Dasein）理解为有规定的存在，……”。

## 论点

论点是诠释者关于该概念的一项可以单独陈述的主张。标题直接写出主张（“尺度的变化引起质变”），不写“第一节”“《小逻辑》中的论述”之类。按论点的逻辑顺序排列，不按书或章节堆叠；同一主张散见多处时合成一个论点。

## 解读

解读讲清**诠释者本人**的立场，主语是诠释者（“黑格尔认为……”“在他看来……”）。可以做三件事：澄清原文难点、补出原文省略的推理、指出对这一论述的常见误读。

解读只陈述，不评判：不说诠释者对错高下，不表达编者或站方观点，不援引其他思想家或二手研究。诠释者本人在原文里批评或回应别人时，可以如实转述这一点，那仍是他的立场，并要有摘录支撑。与其他诠释者的比较交给双链指向的视角。

- 每个论点的解读只说它的摘录和资料覆盖范围内原文支持的内容；补出的推理要标明是在解释原文的意思。
- 格式只用段落和列表（模板不接受解读里的标题、引用块和表格）。
- 关键术语首次出现时注原文，如“定在（Dasein）”，原词取自候选的 `originalTerms`。原文注只写在解读里，摘录保持原样。

## 双链

解读里出现其他概念时加双链。显示文字与规范名相同写 `[[规范名]]`，不同写 `[[规范名|原词]]`，例如 `变易是[[存在|有]]与[[无]]的统一`，可见文字保持原词。

- 目标只能是 `site-terms.json` 中未删除的词条（含别名）或本批已确认的候选；其余概念写成普通文字，否则 `validate` 报 `wikilink.unknown-target`。
- 每个论点内，同一概念只在第一个语义合适的出现处加链；不链当前词条自身。
- 长名称优先：“自为存在”整体链接，不拆出“存在”。
- 有、无、一、多、质、量等单字只在作概念用时加链；“没有”“一般”里的字不是概念。“绝对不同”中的“绝对”可能只是程度副词，先判断语义。
- `@` 是保留字符：`[[词条|显示文字@诠释者]]` 指向某位诠释者的视角，只在该视角已在站上或属于本批时使用。

## 摘录

- 引用写成 `{ "paragraph": "<段落 ID>", "from": n, "to": m }`，n、m 是 `reading.md` 中 ⟨n⟩ 标出的句号（闭区间），只写这三个字段。
- 只引范围内段落；`reading.md` 末尾「范围外注释」一节的段落只供理解，不能引。
- 每段摘录选能直接支撑本论点的连续句子，长段只截关键几句；截断处的“……”由程序加上。
- 同一段落可以服务多个论点或多个概念。
