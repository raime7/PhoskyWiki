## Standards

### STD-1 [P2] CLI 集成测试重新连接真实搜索索引

位置：`tests/integration/reconcile-links.test.ts:10`、`tests/setup.ts:8`、`scripts/reconcile-links.ts:2`。

一期 Spec:107 要求“主缝测试用 fake”。setup 删除 `MEILI_HOST`，但子进程又运行 `dotenv/config`，从本地 `.env` 重新载入真实 Meilisearch 配置。校对脚本逐页执行增量索引同步，因而隔离的测试 PG 内容会进入开发索引。

本次全量运行与独立重跑均失败：预期 `searchSync = disabled: MEILI_HOST is not configured`，实际为 `requested-after-commit; inspect stderr for failures`。即使调用测试前设置空 `MEILI_HOST`，setup 的 delete 仍使它消失并在子进程被重新填入。应在构建子进程 env 时显式禁用搜索或隔离 dotenv，不能仅放宽断言。

测试结束后已从原开发数据库 `localhost/phoskywiki` 重建开发搜索索引，输出 445 篇文档，以清除本次误同步。

### STD-2 [P3] 全 main 仍存在内部实现断言

位置：`tests/integration/auth.test.ts:42`、`tests/integration/search.test.ts:272`。

一期 Spec:101 要求“只断言外部行为”，并规定唯一 HTTP 主缝。认证测试断言账号存储字段与会话行数；搜索测试直接断言 fake 的 `docs` Map，其他回滚场景也如此。这些断言与存储实现绑定，且不能证明用户实际能搜索到新内容或访问受保护接口。数据库可用于夹具准备，但行为应由公开接口或 DOM 验证。

## Spec

### SPEC-1 [P2] 视角编辑页读取的正文与基准修订不是同一快照

位置：`src/app/edit/[pageKey]/page.tsx:67–70`；查询实现 `src/lib/content.ts:189–209`。

ADR-0004:14 要求“编辑起点时的页面当前修订”作为 base，并在页面前进时拒绝覆盖。编辑页通过两个独立查询读取最新正文和最新修订 id。若另一次直编在两个查询的快照之间提交，表单可能得到旧正文和新版 base。此表单提交时 head 与 base 相等，过期校验不会阻止用旧正文覆盖刚发布的新内容。应从同一修订行一次读取 id 与 content，双链映射的一致性也应考虑。

证据类型：静态并发时序分析，未声称已在浏览器复现该交错。

### SPEC-2 [P2] 删除诠释者后讨论锚点仍指向不可见视角

位置：`src/lib/discussion.ts:158`、`:263–269`。

补齐 Spec:49 要求“其下视角从公开链接……中一致隐藏”。讨论只依据视角自身的 `deletedAt` 设置锚点 live，发帖时也没有检查诠释者。现有楼层继续显示有效入口，新帖还可继续引用已经不可阅读的视角。

专用数据库探针实际输出：先带视角发帖 201，删除诠释者 200，`targetVisible:false`，`anchorMarkedLive:true`，再次携带隐藏视角发帖仍 201。探针随后恢复该诠释者。需将讨论锚点的读写校验纳入统一可见性规则。

### SPEC-3 [P2] 搜索回复命中后没有可定位的页面锚点

位置：`src/lib/search/search-types.ts:100`、`src/app/term/[pageKey]/discussion/page.tsx:182`。

一期 Spec:37 要求搜索“正文和讨论帖”。搜索索引包含顶层楼层和嵌套回复，命中链接统一使用 `#floor-<postId>`；页面只有顶层 article 提供此 id，回复 li 没有 id。搜索回复独有内容并点击结果后，浏览器无法定位命中回复，只打开整个讨论页。应为回复提供稳定锚点或调整命中定位策略。

证据类型：索引构建、链接生成与 DOM 源码交叉检查；本次未跑浏览器滚动复现。

### SPEC-4 [P2] 新的同名多义组不能形成消歧义分流

位置：`src/lib/review.ts:612–631`，提交类型校验 `src/app/api/submissions/route.ts:13`。

一期 Spec:24 要求“在同名多义词……上被消歧义页分流”。现有演示种子可以展示此能力，但公开新建、导入路径不会创建消歧义页，也没有单独的创建入口。新建两个括号限定的同名词条后，基准名称没有对应的分流页，词条侧也无分流入口。

专用数据库中通过真实提交 route handler 新建全新组的“（哲学）”与“（历史）”词条，两次均返回 201，`getTermDisambiguation` 返回 null。这是新内容的功能缺口；修复不限定必须新增某种编辑器。

### SPEC-5 [P2] 信息框未实现关键文本结构化信息

位置：`src/db/schema.ts:73–96`，词条/诠释者信息框及新建表单。

一期 Spec:29 明确要求“结构化信息（领域、别名、关键文本等）”。当前词条只有简介、别名，诠释者只有简介、生卒年等；关键文本没有存储、提交、导入或信息框展示通路。正文引用栏并不提供该结构化信息。补齐 Spec 只扩展既有三个字段，且明确不替代原一期，因此该原始需求仍未交付。
