## Question

在“同名共用词条、同一诠释者仅一篇分章视角”的既定规则下，存量分拆词条、消歧义页与重复视角应如何归并，才能保留内容、历史和所有既有入口？本议题是 HITL 决策，须与维护者讨论后记录结论，不能把建议当成已获确认的迁移命令。

已核实的约束：`src/db/seed.ts` 包含“价值（政治经济学）”“价值（哲学）”和“价值”消歧义页；两边均有编委会视角。`src/db/schema.ts` 的标题及视角唯一约束包含已删除记录；`src/lib/resolve-page.ts` 仅支持同一 id 的旧 slug 跳转。`src/lib/page-links.ts` 保留已解析目标 id，重新校对不会自动合并身份；历史只能同页比较和回滚。尚未盘点实际数据库。

请逐项确认：

1. 是否采用显式归并清单与旧页面到保留页面的兼容映射，保留来源历史，不自动将所有括号标题归为一组？保留 id、章节、置顶与隐藏状态如何进入预览？
2. 重复视角是否整理为保留页的新修订，并保留来源修订原归属？旧历史回滚、页面恢复与撤销合并如何区分，避免复活已合并页面？
3. 受影响待审提交是否以明确原因结束并通知重提，保留旧投票记录，禁止静默更换目标与 base？
4. 如何保留讨论帖子 id、回复树、旧 URL fragment 和锚点？建议任一来源讨论锁定时合并结果仍锁定，再由管理员显式解锁。
5. 旧词条、消歧义、视角和讨论 URL，以及已解析双链、旧名称的新链接，如何到达唯一的保留身份？如何避免图谱、热度、搜索、兴趣和 Agent 上下文重复计数或暴露隐藏内容？

建议路线供讨论：先生成可审阅清单，再在数据库副本 dry-run；增量添加兼容读取能力后，以分组事务、head 校验和可重复执行的迁移实施。保持原数据可追溯，不以重新 seed 代替迁移。

结案应明确上述规则、失败和恢复策略，以及公开行为验收情景；实际开发和生产数据迁移留给后续实施任务。
