# R08: 从驳回记录继续修改并重提

> 已发布：https://github.com/raime7/PhoskyWiki/issues/26。优先级：P2。对应 Spec 用户故事：13–18。

## Parent

https://github.com/raime7/PhoskyWiki/issues/18

## What to build

编者从自己的驳回详情带回完整提案，结合最新内容修改后产生独立的新提交，失败时保留草稿。

遵循父 Spec 与 ADR-0001～0004；每项功能连同相关接口、页面及外部行为测试一起交付。测试以 HTTP 和渲染 DOM 为主，使用隔离的真实 PostgreSQL；纯函数测试仅作补充。

## Acceptance criteria

- [ ] 覆盖新建词条、视角、诠释者及词条/视角编辑；复用编辑器并预填全部可编辑字段，显示驳回理由。
- [ ] 目标 head 前进时展示最新版与原提案，要求编者确认整理结果；不只替换 base 后静默提交。
- [ ] 新草稿独立保存；网络或校验失败保留草稿，只在新提交创建或管理员直接生效成功后清理对应草稿。
- [ ] 新提交关联原驳回记录，旧状态、理由和投票不变；重新校验权限、标题与父页面，并重新快照 quorum。
- [ ] 普通编者只能从自己的记录重提；目标失效时解释原因、保留草稿，不自动恢复页面。
- [ ] 浏览器完成驳回→详情→编辑→重提→受理→公开闭环，覆盖过期基准、权限及失败重试；HTTP 验证终态与新记录。
- [ ] 仅依赖词条提案类型已交付，不依赖历史回滚 UI；父页面受理修复的组合场景在最终验收验证。
