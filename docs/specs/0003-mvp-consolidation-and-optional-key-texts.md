# Spec: 一期 MVP 收束——同名词条归并、可选关键文本与行为修复

> 承接一期 MVP 及其补齐批次，审查基线为 main `164cd6c0006b4b0f40c1e30cf86dc7b3fc468119`。本规格采用用户在 wayfinder 中确认的最新产品规则，替代旧规格的独立消歧义分流要求和关键文本强制要求。

> 已发布为 [Spec: 一期 MVP 收束——同名词条归并、可选关键文本与行为修复](https://github.com/raime7/PhoskyWiki/issues/33)，状态为 ready-for-agent。

## Problem Statement

读者在阅读同一个词时，不应因为哲学、政治经济学等领域划分而被送到多个词条。当前“价值”示例分成两个词条和一个消歧义页，通俗解读也分散在两篇编委会视角中，破坏了“词条聚合多个诠释者”的阅读结构。

关键文本可以帮助阅读，但其缺失不应成为词条不合理的自动判据。此前围绕强制补录、隐藏来源历史和长期旧入口兼容提出的方案超出了当前 Wiki 的需要。管理员应保留内容判断权，现有内容应直接归并，不需要的隐藏内容应清除。

此外，当前编辑页可能将旧正文与新基准修订组合，导致覆盖他人修改；讨论锚点可能指向不可阅读的视角；搜索回复后无法定位命中内容。CLI 集成测试还可能重新启用开发搜索配置，部分测试依赖内部存储断言，降低了验收结果的可信度。

## Solution

让同名概念共用一个词条枢纽，各诠释者的视角聚合在其下。同一诠释者只保留一篇视角，用章节区分领域或含义；编委会视角也遵守这一规则。直接合并现有分拆内容，迁移仍保留的公开关系，清除隐藏内容和废弃来源，不建设通用合并平台或长期来源档案。

提供可选关键文本信息，允许不填，由管理员判断词条内容是否合理。沿用现有审核、修订和导入流程处理可选字段，不要求旧数据补录或旧提案因缺字段重提。同时修复编辑一致性、讨论有效性、搜索定位和测试隔离，以用户实际可见的行为重新验收一期。

## User Stories

**同名聚合与分章阅读**

1. 作为读者，我想通过同一个词条阅读跨领域的不同解释，以便不因领域划分来回切换词条。
2. 作为读者，我想在词条下看到各诠释者的视角入口，以便按思想家的解释继续阅读。
3. 作为读者，我想同一诠释者对同一个词的不同含义在一篇视角内分章，以便完整理解其解释。
4. 作为读者，我想在一篇编委会通俗视角中看到各含义的概述，以便先建立基本认识。
5. 作为编者，我想新建同名词条时被引导到已有词条，以便通过补充视角或章节参与，而非继续按领域拆词条。
6. 作为编者，我想已有相同诠释者视角时能编辑该视角，以便不会重复创建同一组解释。
7. 作为读者，我想归并后仍能阅读原先公开的各篇解释，以便内容不会因整理而丢失。
8. 作为读者，我想归并后分类、搜索和相关发现指向统一词条，以便不会看到重复结果。
9. 作为读者，我想保留内容中的普通双链和精确视角链接仍可到达正确页面，以便不会遇到内部断链。
10. 作为参与讨论的编者，我想公开讨论和回复关系随词条归并保留，以便已有交流仍可阅读。
11. 作为读者，我想讨论中的有效视角锚点指向归并后的视角，以便理解讨论针对哪篇解释。

**存量清理与管理**

12. 作为管理员，我想直接归并同名内容并清除废弃来源，以便不必维护两套内容或来源档案。
13. 作为管理员，我想清除已删除或因父页面删除而不可见的存量内容，以便不再为不需要的内容维护恢复与兼容结构。
14. 作为管理员，我想清理范围不波及仍保留的正文、公开讨论和正常页面历史，以便精简数据时不误删有效内容。
15. 作为管理员，我想迁移执行前能看到目标与影响数量，以便确认连接的数据库和实际处理范围。
16. 作为管理员，我想归并失败时不留下部分迁移结果，以便重试不会制造残缺词条。
17. 作为编者，我想旧来源提案不会在归并时被自动发布，以便审核仍有实际意义。

**可选关键文本**

18. 作为编者，我想不填写关键文本也能创建和提交词条，以便不会被统一的文献要求阻挡。
19. 作为管理员，我想根据具体内容判断词条是否合理，以便审核不被“有没有关键文本”代替。
20. 作为编者，我想可选地填写词条核心参考作品或诠释者代表作品，以便为读者提供阅读线索。
21. 作为读者，我想在信息框中按编者安排的顺序看到关键文本，以便选择接下来阅读的作品。
22. 作为读者，我想没有关键文本时页面不出现空占位或缺失警告，以便阅读保持简洁。
23. 作为管理员，我想没有关键文本的旧数据和导入内容仍可使用，以便不需要强制补录。
24. 作为编者，我想旧待审提案不因缺少这个可选字段而被迫重新提交，以便已有工作能继续受理。
25. 作为管理员，我想更新或导入省略字段时保留现值、明确清空时才删除列表，以便不会意外丢失已填信息。
26. 作为管理员，我想填写后的关键文本进入既有修订与回滚，以便能纠正错误修改。
27. 作为管理员，我想回滚缺少该字段的旧修订时保留当前关键文本并看到简短说明，以便不会把未知历史当作空值。

**编辑、讨论与搜索修复**

28. 作为编者，我想编辑起点的正文、基准修订和预览链接相互一致，以便提交准确对应我实际读到的内容。
29. 作为编者，我想其他人发布新版后，旧基准提交不能覆盖它且草稿仍保留，以便整理后再提交。
30. 作为读者，我想讨论只提供有效的视角入口，以便不会从正常锚点进入不可阅读页面。
31. 作为编者，我想新帖不能锚定不存在或不可见的视角，以便讨论不会从创建时就携带失效入口。
32. 作为读者，我想搜索到回复后直接定位那条回复，以便无需在整页讨论中再次查找。

**可靠验收**

33. 作为维护者，我想运行集成测试不会向开发搜索索引写入测试内容，以便测试不污染实际阅读结果。
34. 作为维护者，我想认证和搜索回归通过公开行为验证，以便内部存储重构不会无故破坏测试。
35. 作为维护者，我想在归并和清理后验证唯一词条、分章视角、有效双链与讨论，以便知道新产品规则已经生效。
36. 作为维护者，我想验收明确列出未执行的浏览器或真实服务检查，以便不会将缺少证据误报为通过。

## Implementation Decisions

### A. 领域模型与规格变更

- 词条继续是导航枢纽，正文继续放在视角；同名概念的跨领域差异不创建另一层实体，也不构成另建词条的理由。
- 保留“词条 × 诠释者”的唯一约束。对同一组增加解释应编辑原视角，以 Markdown 章节表达含义差异；不增加领域维度的复合身份或新精确链接语法。
- 同步调整创建入口、重复标题提示、编委会示例、导入约定和种子，使“价值”成为一个词条，编委会解读包含原有两类内容的章节。
- 不再提供独立消歧义维护流程。现有消歧义类型和路由停止承载新内容；实施时清理不再使用的分流逻辑和残留引用。
- 本规格明确修订原一期的消歧义故事与 ADR-0003 的括号分词条、独立消歧义约定；对应决策变更需留文档记录，不让新代码与旧规则并列为有效要求。

### B. 一次性同名归并

- 在实际目标数据库中识别原先按领域拆分的同名组，为每组选择一个保留词条。只处理语义已明确的同名组，不对所有括号标题进行无差别字符串截断。
- 优先保留已有适合承接的词条身份；若没有裸名词条，可将一个来源词条改为统一名称。普通改名继续遵循既有 id 寻址规则。
- 不重复的诠释者视角保留身份并调整归属；重复视角选择一个保留身份，将应保留的公开正文整理为不同章节，产生新的合并结果修订。不能为绕过唯一约束而丢弃其中一篇公开解释。
- 合并分类并去重；将公开讨论、回复关系与有效视角锚点调整到保留对象。视角置顶合并为一个状态；讨论任一来源锁定时保留锁定，管理员可沿用原入口解锁。
- 保留内容中的普通和显式双链一次性改向正确对象。正文需要改写时通过新修订表达，不能只修改显示文字而留下错误解析目标。完成后重建反链、热度、图谱、搜索及相关发现，避免重复身份、重复计数与悬空引用。
- 不新增通用归并后台、来源历史浏览、撤销合并或永久重定向体系。废弃来源 URL 不作为兼容承诺；站内保留内容及导航必须更新，不继续输出这些废弃地址。
- 迁移完成后清除废弃分拆词条、旧消歧义页及不再需要的重复视角来源。保留页有自己的历史和新合并修订，不伪造跨来源的共同历史。

### C. 隐藏内容与依赖清理

- 本次清理包括：已软删除的页面与帖子、因词条或诠释者被删除而不可公开的视角，以及完成内容迁移后废弃的来源页面。
- 同步清理仅附属于这些对象的旧修订、提案、投票和其他依赖记录。仍被有效对象引用的数据应先在本次迁移中正确处理关联，不能留下悬空外键或误删共享内容、图片。
- 正常保留页面的旧修订与待审提案不因为“非公开”而被全库清空；公开讨论也不属于隐藏清理对象。旧来源待审内容不得自动改目标、换基准或复用批准票后发布。
- 以上是本次存量整理的清理范围，不擅自将全站今后的软删除改为永久删除。正常内容后续仍适用既有审核、修订、回滚与删除规则。
- 这是对原“所有来源历史与隐藏记录均长期保留”迁移提案的替代，以及本次清理对象对既有保留规则的明确例外；不是对全站历史留存规则的整体废除。
- 实施前核实数据库目标、生成实际影响数量并保留普通运维备份。按同名组事务处理，执行前复核页面状态，失败不部分生效；重跑识别已处理组。无需将备份包装成 Wiki 内的归档功能。

### D. 可选关键文本

- 词条与诠释者可填写有序作品列表；作品名、作者、年份、链接表达原先约定的阅读线索。列表整体可缺省，不设置作品数量或权威性门槛，不把作品建成独立页面。
- 没有列表时不阻止创建、提交、受理或导入，也不展示空区块。填写时仅校验可用的数据形状和链接等基础格式；内容质量交给管理员判断，不以“无关键文本”自动判定不合格。
- 复用所属页面的提交、草稿、受理、驳回重提、修订 diff 与回滚通路；诠释者的可选信息修改也须具备相同闭环，不另建审核系统。
- 新建缺省为空；更新或导入省略字段表示不改变，显式空列表表示清空。区别缺省与清空，不要求旧数据补录，也不因旧提案未携带字段而强制重提。
- 新修订记录实际字段值。旧快照缺失字段时，回滚恢复它实际记录的字段并保留当前关键文本，预览用一句话说明该字段未被旧修订记录；不猜测历史、不清空未知值。
- 既有受理票数、管理员直编和基准过期校验继续适用。可选字段不等于免审核，管理员判断内容合理性也不改变普通提交的受理规则。

### E. 已有行为修复

- 编辑读取返回同一修订行的正文与基准 id。预览所依赖的解析关系与编辑起点保持一致；需要多次查询时采用能够保证同一读取快照的事务，不能把并行改串行或默认事务当作充分修复。
- 受理时继续校验 head 与基准。页面已前进时不能覆盖新内容，按已有规则处理过期提交并保留客户端草稿。
- 讨论锚点展示与新帖校验复用完整可见性规则：视角及所属词条、诠释者都可阅读。一次性清理不能替代对未来删除、恢复或目标失效的正确处理。
- 对正常流程中保留的讨论，目标暂不可用时不输出有效视角入口；恢复父页面只恢复未被独立删除的视角入口。对本次已永久清理对象不建设恢复展示。
- 楼层与回复提供和搜索结果一致的稳定锚点。若页面存在折叠或分页，直接访问结果必须让命中项实际可见。

### F. 测试隔离与交付顺序

- 测试子进程显式禁用开发搜索配置，防止重新加载环境文件后启用真实 Meilisearch；不要通过放宽原失败断言掩盖污染。
- 认证和搜索集成测试改为验证会话、访问权限和公开搜索结果，替换对会话存储行或 fake 内部 Map 的断言。
- 先修复测试隔离，再修复编辑、讨论与定位；随后实现可选字段、归并与清理，更新种子和规格，最后重新验收整批行为。

## Testing Decisions

- 沿用一期已经约定的唯一主缝：HTTP 边界，包括 route handlers 与 SSR 页面；不新增平行测试体系。浏览器负责验证真实交互，纯函数单元测试仅补充无 IO 规则。
- 好测试断言 HTTP 响应、渲染 DOM、可见页面和公开搜索行为。数据库用于真实运行与夹具准备，不能用内部行数或 fake 私有状态代替用户行为。
- PostgreSQL 使用隔离数据库并执行真实迁移；主缝搜索与对象存储使用既有 fake。Meilisearch 与 R2 分别保留独立真实契约测试，使用专用索引/资源，不能污染开发环境。
- 复用既有提交状态机、词条元数据回滚、删除可见性、双链、搜索、CLI 报告和浏览器导航测试模式，修正旧消歧义预期而非仅删除测试。
- 归并夹具至少覆盖：同名不同诠释者、同名相同诠释者、两个编委会视角、分类重叠、公开楼层与回复、普通/显式双链、已删除父页面下视角、废弃来源及正常页面的历史和提案。
- 通过公开页面验证仅有一个同名枢纽、每位诠释者仅一篇视角、需要保留的正文完整分章、分类和讨论可读、内部链接有效、搜索与图谱没有重复来源。清理报告明确目标和数量；重复执行不再产生额外变更。
- 可选字段覆盖：完全不填、主动填写与排序、显式清空、旧提案受理、导入省略、旧快照回滚及新快照回滚。不能只证明数据库存下字段，必须验证公开信息框及审核可见时机。
- 并发回归安排另一笔提交穿插编辑状态读取，验证内容/base 一致，旧基准不能覆盖新版；验证草稿保留。纯粹断言某函数被调用一次不足以证明行为。
- 浏览器覆盖同名枢纽与分章阅读、编辑到受理、可选信息框、双链落点、讨论锚点和搜索回复定位；搜索用回复独有文本，点击后检查命中回复实际可见。
- 运行类型检查、lint、默认构建与相关全量测试。上一轮 main 的通过结果不作为新实现证据；缺凭据或环境受限的检查单列未验证项，不声称全部验收通过。

## Out of Scope

- 独立消歧义编辑器、按领域拆分的新身份模型、独立作品页与关键文本强制补录。
- 通用内容合并平台、跨来源历史浏览、撤销合并功能、隐藏内容长期档案与永久旧入口兼容。
- 全库清空旧修订或待审提案、用重新 seed 替代真实内容归并、擅自把以后全站删除改成永久删除。
- 改变审核票数与权限模型、二期功能、界面高保真重设计及生产部署。
